# v5.3 · Device Backend + L0 Topic Intelligence

> zhenji v5.3 architecture roadmap  
> 当前稳定版本仍为 5.2.2。本文定义 v5.3 的详细架构与验收目标，不代表这些能力已经实现。

v5.3 将原本分开的两个目标合并：

```text
Device Backend Layer
+
L0 Topic Intelligence
```

其中 **Browser Intelligence 是 v5.3 的 P0 实际开发目标**；Android Backend 进入统一架构，但 Android 实际平台支持不阻塞 v5.3 发布。

---

# 1. 目标

甄姬不绑定单一设备。

统一原则：

```text
Device Capability 决定能做什么
Permission Layer 决定允许做什么
Action Recipe / Browser Definition 决定如何执行
```

上层 Collector、Runtime、Facts / Features / Knowledge 不应该直接依赖 iPhone、Android 或浏览器的具体实现。

---

# 2. v5.3 只支持三种 Backend

```text
A. Real Device iOS
B. Real Device Android
C. Browser Intelligence
```

不采用 Headless Mode。

---

# 3. DeviceBackend 统一接口

建议接口：

```python
class DeviceBackend:
    def connect(self): ...
    def disconnect(self): ...
    def health_check(self): ...
    def state(self): ...
    def screenshot(self): ...
    def navigate(self, target): ...
    def click(self, target): ...
    def tap(self, target): ...
    def swipe(self, direction, amount=None): ...
    def input(self, text): ...
    def extract(self, query=None): ...
    def back(self): ...
```

不是所有 Backend 都必须真实实现每个动作；不适用的能力需要显式声明 unsupported，而不是静默模拟。

建议能力对象：

```yaml
backend: browser
capabilities:
  screenshot: true
  navigate: true
  click: true
  tap: false
  swipe: false
  input: true
  extract: true
  app_recommendation_feed: false
```

---

# 4. Backend A · Real Device iOS

```text
backend: ios_mirror
mode: real_device_ios
```

定位：旗舰执行后端。

底层：

```text
iPhone
→ iPhone Mirroring
→ phone-harness
→ DeviceBackend
```

优先能力：

```text
真实 App 浏览
高价值账号使用
推荐流研究
搜索
分享链接获取
评论读取
未来 L1 / L2 / L3
```

高价值长期账号默认留在真实 iPhone App。

现有 iPhone 代码在 v5.3 中的主要任务不是重新开发，而是逐步适配统一 DeviceBackend 接口，避免上层继续写死 iPhone。

---

# 5. Backend B · Real Device Android

```text
backend: android_device
mode: real_device_android
```

定位：兼容真实设备后端。

底层：

```text
Android
→ phone-harness Android backend / ADB 能力
→ DeviceBackend
```

原则：

```text
Android ≠ iOS 坐标替换
Android ≠ 直接复用 iOS Recipe
```

同一平台动作必须分别录制与验证：

```text
xhs.share_link.ios
xhs.share_link.android
```

Android 进入 v5.3 的内容：

```text
统一 Backend 接口
能力声明
Recipe 设备绑定规范
未来平台接入位置
```

Android 不阻塞 v5.3 发布。

任何 Android 能力只有完成真实 Android 环境下的 Recipe 录制、状态验证、失败恢复与重复测试后，才允许标记 supported。

---

# 6. Backend C · Browser Intelligence

```text
backend: browser
mode: browser_intelligence
```

定位：没有手机时的主要公开信息研究后端，也是 v5.3 的 P0 实际开发目标。

Browser 不是手机模拟器，也不应该伪装成真实 App 行为。

## 6.1 目标能力

优先服务 L0：

```text
公开搜索
公开帖子读取
公开账号主页研究
公开评论读取（平台允许时）
对标账号研究
竞品分析
URL / 媒体接入现有 Pipeline
```

建议第一阶段从小红书 Web 开始。

## 6.2 Browser 不承担的能力

```text
不把网页推荐流当成 App 推荐流
不继承 iOS / Android Action Recipe
不假设浏览器账号状态等价于手机账号状态
不优先承担 L1 / L2 / L3
```

若未来某个平台 Web 端稳定支持互动或发布，也必须按独立 Browser capability 重新评估，而不是自动开启。

## 6.3 建议 Browser Backend 结构

```text
scripts/device/
├── base.py
├── ios_mirror.py
├── android_device.py
└── browser/
    ├── backend.py
    ├── session.py
    ├── state.py
    └── extractors/
        ├── profile.py
        ├── post.py
        ├── comments.py
        └── search.py
```

## 6.4 Browser 执行定义

Browser 不使用真机坐标 Recipe，但仍需要等价的声明式执行定义与状态验证。

例如：

```yaml
platform: xhs
backend: browser
action: search
initial_state: searchable_page
steps:
  - focus_search
  - input_query
  - submit
post_conditions:
  - results_visible
failure_states:
  - login_wall
  - verification_required
  - unsupported_page
```

目标依然是：

```text
稳定定义
→ 可重复执行
→ 状态验证
→ 失败可识别
```

而不是每次临时探索网页。

# 7. v5.3 的 L0 Topic Intelligence

Device Backend 本身不是最终产品价值；v5.3 必须让新的 Backend 服务于 L0 选题。

## 7.1 搜索选题

```text
用户主题 / 品类 / 人群 / 问题
→ Browser / Real Device Search
→ 代表作品
→ 评论
→ 用户问题 / 痛点 / 争议 / 高互动结构
→ Pattern
→ Topic Pool
```

优先使用 Browser Intelligence 实现大样本公开搜索研究。

## 7.2 对标账号选题

```text
1–N 个对标账号
→ 近期内容 + 高表现内容
→ 评论
→ 主题 / Hook / 封面 / 结构 / 互动比较
→ 可迁移 Pattern
→ 自己的选题
```

## 7.3 自己的帖子 / 评论读取

v5.3 只先完成 L0 读取与分析：

```text
自己的帖子
→ 读取表现
→ 读取评论
→ 评论分类
→ 内容机会 / 用户需求
```

点赞、回复分别留给 v5.4 / v5.5。

## 7.4 Topic Pool

搜索、对标账号、自有账号最终统一进入：

```text
Evidence
→ Facts
→ Features
→ Pattern
→ Topic Pool
```

不得让 Browser 数据形成另一套孤立 schema。

---

# 8. Action Recipe / Browser Definition 绑定规则

真机 Recipe 必须声明设备：

```yaml
platform: xhs
backend: ios_mirror
action: share_link
```

Android：

```yaml
platform: xhs
backend: android_device
action: share_link
```

Browser：

```yaml
platform: xhs
backend: browser
action: search
```

禁止一个 Recipe 假设所有 Backend 一致。

---

# 9. 开发完成标准

## 9.1 真机 Backend

任何真机能力上线必须满足：

```text
Backend ready
+
Action Recipe ready
+
真实设备录制
+
前置状态验证
+
post-condition
+
失败恢复
+
重复测试
```

## 9.2 Browser Backend

Browser 能力上线必须满足：

```text
Browser Backend ready
+
页面执行定义 ready
+
页面状态验证
+
失败状态定义
+
重复测试
+
结果进入统一 Facts / Features / Knowledge
```

Browser 不要求真机录制，但不能降低“可重复、可验证、可失败”的标准。

# 10. v5.3 优先级

```text
P0  DeviceBackend 基础接口
P0  现有 iPhone Mirror 接入统一接口
P0  Browser Intelligence Backend
P0  小红书 Browser Search / Post / Profile 基础路径
P1  搜索选题
P1  对标账号选题
P1  自己帖子 / 评论 L0 读取
P1  Topic Pool
P1  Android Backend 接口与 Recipe 规范
P2  Android 各平台真实 Recipe 录制与验收
```

其中：

```text
Browser Intelligence 必须可用，才算 v5.3 的核心目标达成。
Android 实际平台支持可以后续逐项完成，不阻塞 v5.3。
```
