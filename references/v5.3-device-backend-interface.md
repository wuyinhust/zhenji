# v5.3 Device Backend Interface（设备后端接口）

> zhenji v5.3 architecture roadmap
>
> 本文只定义架构，不实现具体 Android / Browser 后端。

## 目标

甄姬不绑定单一设备。

设备负责提供执行能力，Skill 根据当前环境选择最佳后端。

```text
Device Capability 决定能做什么
Permission Layer 决定允许做什么
Action Recipe 决定如何执行
```

---

# Backend 层

统一接口：

```python
class DeviceBackend:

    connect()

    disconnect()

    state()

    screenshot()

    navigate()

    tap()

    swipe()

    input()

    back()

```

上层 Collector、Action Recipe、Runtime 不直接依赖具体设备。

---

# v5.3 支持的三类 Backend

## 1. iPhone Mirror Backend

```text
backend: ios_mirror
mode: real_device_ios
```

定位：旗舰模式。

能力最高：

- 真实 App 环境
- 真实账号
- 推荐流研究
- 分享链接获取
- 后续互动与发布

优先级：★★★★★

---

## 2. Android Device Backend

```text
backend: android_device
mode: real_device_android
```

定位：兼容真实设备。

要求：

- 支持 phone-harness Android backend
- 独立 Action Recipe
- 不复用 iOS 坐标

例如：

```text
xhs.share_link.ios

xhs.share_link.android
```

必须分别录制、验证。

优先级：★★★★☆

---

## 3. Browser Backend

```text
backend: browser
mode: browser_intelligence
```

定位：无手机情况下的公开信息研究。

不是手机替代品，而是 Web Intelligence（网页情报）后端。

支持：

- 公开搜索
- 公开账号研究
- 公开内容读取
- 竞品分析
- 数据采集

限制：

- 不等价于 App 推荐流
- 不假设拥有真实设备行为
- 不自动继承手机 Action Recipe

优先级：★★★☆☆

---

# 不采用 Headless Mode

甄姬不增加纯无设备自动化模式。

没有设备时：

```text
Browser Backend
        ↓
已有素材分析
        ↓
内容理解
```

而不是模拟不存在的手机能力。

---

# Action Recipe 绑定规则

Recipe 必须声明设备类型：

```yaml
platform: xhs
backend: ios_mirror
action: share_link
```

Android：

```yaml
platform: xhs
backend: android_device
action: share_link
```

Browser：

```yaml
platform: xhs
backend: browser
action: search
```

禁止：

```text
一个 Recipe 假设所有设备一致
```

---

# 开发完成标准

任何设备能力上线必须满足：

```text
Backend
+
Action Recipe
+
真实环境录制
+
状态验证
+
失败恢复
+
重复测试
```

只有通过以上标准，平台能力才从 roadmap 进入 supported。

---

# v5.3 目标

不是增加功能，而是完成设备抽象：

```text
phone-harness
      ↓
DeviceBackend
      ↓
Action Recipe
      ↓
Platform Collector
```

为后续 Android、Browser、多平台扩展提供统一基础。
